## What Section 3 produced

### Which feature for which task

| Task | Feature | Why not the others |
| --- | --- | --- |
| Rewrite one paragraph of a reply | A chat | A one-off task needs no shared knowledge and no saved result |
| A policy question that comes back every day | A Project with the policy as knowledge | The same source and the same rules for every chat |
| A rule that is not in our files (EU right of withdrawal) | Research (paid plan) or web search for one fact | The answer is outside our files and needs sources |
| A checklist the team will edit and pass around | An artifact (Docs), or a .docx file | It is a result to keep, edit and share |

### Which model for which task

| Task | Model |
| --- | --- |
| Many short, routine replies | The lightest model that passes the bar on typical and hard cases (try Haiku, then Sonnet) |
| A rare, hard analysis with conflicting constraints | The most capable model available (Opus on a paid plan) |

### Handoff summary template

```text
Decisions: what we decided, and why.
Constraints: limits that still apply (for example: "the 30-day return window does not change; only the damaged-item exception is under review").
Sources: the files and sections we relied on.
Open questions: what is still unknown, and who can answer it.
```

Check the summary against the conversation before you use it: qualifications are the first thing a summary loses.
